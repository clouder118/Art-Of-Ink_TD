# 原生工程验证证据

这些文件记录 TD 内实际渲染的山水，未记录摄像头画面或手部关键点。自动轨迹与真实手势验收分别记录，不能互相替代。

后续手势运动连续性优化、20/30 FPS 对照和用户反馈见 [连续受力验证](smoothness/README.md)。首版长时间与离线验收的范围保持按下文记录说明。

2026-10-22 新增的三种摊手循环效果，规格及真实验收见 [摊手效果说明](../palm-effects.md)，方向检查与恢复测试见 [原生测试结果](palm-effects/native-validation.json)。该目录的 PNG 均为自动效果测试结束时的山水截图，不含摄像头画面。

## 流动与恢复

在 TD 的 Python 环境运行 `TD/tools/validate_fluid.py`。工具临时替换运行时的控制器，摄像头识别保持开启；测试完成或捕获异常后恢复真实控制器。原生 GPU 网络和原山水素材均参与测试。

顺序为：基线 0.6 秒、慢推 4 秒、恢复 8 秒、快推 1 秒、恢复 8 秒。快慢推动均横跨相同的半幅画面，测试结束的图像与初始基线比较。录像仅含山水；编码采用 TD 可用的软件 MPEG-4，不要求商业版 H.264 编码。为视频编码将输入等比适配到 1280 × 648，作品输出仍为 1280 × 647。录像名义帧率 60 FPS 不代表实际渲染持续达标，性能由单独的基准测量。

- [对照录像](flow-comparison.mp4)
- [32 位颜色反馈测试结果](flow-validation.json)
- [修复前 16 位颜色反馈结果](flow-validation-16bit.json)
- `baseline.png`、`slow.png`、`restore_slow.png`、`fast.png`、`restore_fast.png` 为各段结束时的原生 TOP 截图。

修复前，停手 8 秒的平均 RGB 差异仍分别为慢推结束时的 59.8%、快推结束时的 46.9%。速度场已经归零，残留来自低精度颜色反馈的量化误差。改为 32 位颜色反馈后，相同测试的残留降至约 2.0% 和 2.3%，快推最大速度约为慢推的 2.43 倍，所有采样均为有限数值。

回归要求：存在局部图像变化，快推的最大速度大于慢推的 1.2 倍，停手 8 秒的平均差异降至对应推动结束时的 10% 以下。此阈值检查数值行为，不代表用户已接受所有视觉效果。

## 持续性能与音频

在已启动的 TD 工程中运行 `TD/tools/benchmark.py`，保持 Perform 山水窗口在前台。预热 5 秒，随后执行 330 秒的空闲、慢推、快推、恢复与混合输入，轨迹以当前识别目标频率更新，画面继续独立渲染；相同采样不会逐渲染帧重复施力。摄像头识别、音乐和展示同时开启，不进行录像。

结果写入 `benchmark.json`；`finished: false` 只表示阶段性记录。包含平均 FPS、帧间隔 P50/P95/P99、超过 20 ms 的比例、每秒抽样的识别耗时和最新结果年龄、音乐播放位置及循环次数、静音参数检查。最新结果年龄包含等待下次识别采样的时间，不是光学测得的端到端跟手延迟。

## 真实交互与窗口验收

- [真实手势录像](real-gesture-demo.mp4) 与 [录像元数据](real-gesture-recording.json)：30 秒，真实控制器、摄像头 `ready`，仅录山水画面。交付视频转为 H.264 后完整解码 1801 帧，1280 × 648，不含声音及摄像头预览。
- 用户确认左手稳定且离开后右手正常接管，音乐播放正常；随后按慢移、快移、静止、收指后观察的步骤，确认局部流动、消散与原画恢复“符合预期”。这是用户现场验收，不是自动轨迹结论。
- [关闭预览](preview-close.json)：实际点击摄像头预览小窗右上角关闭按钮，预览关闭后摄像头仍为 `ready`，持续接收新识别结果。最新需求为每次启动默认打开小窗，手动关闭仅隐藏预览。
- [缺失资源故障](missing-resources.json)：以临时资源路径注入启动失败，验证控制器停止且速度输入为零，随后恢复正常资源路径。
- [真实手势性能](real-performance.json) 单独记录完整展示配置；`finished: false` 表示尚在测量。已撤回的预览绘制优化见 `real-performance-preview-suppression.json`，平均仅 34.59 FPS，不能作为性能通过证据。
- [分离窗口对照](performance-isolation.json) 与 [同步模式对照](window-sync-probe.json) 显示第二原生窗口导致明显降速，因此交付改为主窗口内的预览浮层。开发进程中五分钟浮层测量见 `real-performance-overlay-before-coldstart.json`，平均 37.49 FPS，仍未达标。
- `TD/tools/monitor_runtime.py` 可只读采样交付工程的状态文件，报告为每秒抽样的滚动 600 帧统计；窗口相互重叠，不能将采样均值当成独立计数得到的全程平均 FPS。该工具不添加 TD 测试节点、不注入输入，也不记录影像或关键点。
- [最终冷启动工程的五分钟观察](cold-start-performance.json)：298 次采样，滚动 FPS 均值约 59.91、最低 58.15，滚动 P95 帧间隔最高约 17.74 ms；摄像头均为 `ready`、没有节点错误，用户确认没有明显卡顿。该结果与旧开发进程的测量分开保存。
- [离线迁移验收](offline-acceptance.json)：Git 归档迁移副本的资源测试与工程哈希通过；用户实际关闭 TD、断网并重开迁移工程后，确认预览、手势与音乐均正常。

基准完成会恢复真实控制器与原静音状态。真实手部动作、视觉接受程度、离线重启和扬声器实际听感仍须单独验收。
