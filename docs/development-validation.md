# 开发与实机验证记录

日期：2026-10-21。目标环境：Windows，TouchDesigner 2025.32820，RTX 4060 Laptop GPU，BisonCam,NB Pro 内置摄像头。

## 已验证

- TD 原生节点显示 1280 × 647 原山水图，GLSL 速度平流、旋度、压力投影和图像平流网络无节点错误。
- MediaPipe Tasks Vision 1.0.1 在 TD 内置 Web Render TOP 中使用本地模型运行，识别结果通过 TD 自带 Web Server DAT 传给控制器。
- 真实用户先反馈“画面存在，但无法推动”；调试画面中随后确认“能看到手和山水画的水墨交互，不过现在的效果看着很弱”。说明闭环能触发，但初始视觉推动不足。
- 单独将速度注入强度 `Gain` 从 8 改为 24 后，用户确认“推动明显，强度合适”。默认值据此保留为 24；没有同时放宽手势规则或改变恢复参数。
- 原生 GPU 固定轨迹探针（初始 Gain 8）测得：RGB 平均变化 0.0009643，超过 0.005 变化阈值的像素比例 3.43%，最大速度场分量 12.664。此探针证明实际图像发生变化，不替代人工视觉验收。
- 14 项自动测试通过：12 项控制器行为测试、2 项离线资源测试。测试使用 TD 自带 Python 3.11.10，无额外测试依赖。
- 已停止临时手势角度采样探针。运行时诊断不保存摄像头画面；本地开发日志与探针输出位于 Git 忽略的 `TD/.runtime/`。
- 干净工程导出后以 `toeexpand` 检查：没有 `/ink_dev`、`/ink_probe`、手部关键点存储；资源采用工程相对路径，自动进入 `/artofink/output_window` Perform 展示。
- 使用 Git 归档复制到独立目录后，14 项 Python 测试仍通过，分发的 JS/WASM/模型字节校验一致。新 TD 进程通过原生项目加载进入迁移工程，自动出现 1280 × 647 山水画面。
- 迁移后的首次摄像头启动出现 `NotReadableError`。新增实体摄像头优先选择和有限重试后，重新加载识别页面恢复为 `ready`，本机推理约 14 ms；空闲展示约 60 FPS。尚需对修复后的完整构建再做冷启动复验。
- 新增 3 项 Node 自动测试，直接执行实际分发的摄像头适配器，验证 OBS 排在首位时选择实体摄像头、暂时不可读后的恢复、显式设备选择与重试次数上限，全部通过。
- 后续增加张掌、握拳与低置信度拒绝测试，以及预览绘制／背压、识别线程后端降级和图像释放验证，目前为 16 项 Python + 6 项 Node 测试通过。
- 补齐可调的速度耗散与指尖平滑参数，默认分别为 7.67/秒、0.035 秒，推动强度仍为用户确认的 24。
- 原生慢推/快推/停手恢复验证发现 16 位颜色反馈的量化残留：停手 8 秒后仍有约 47%–60% 的平均图像差异。将山水颜色反馈单独升级为 32 位后，残留降至约 2%，严格恢复回归通过，速度场保持原模拟精度。对照数据、原生截图和山水录像见 [验证证据](validation/README.md)。
- 用户真实双手测试反馈：“左手稳定，移开后右手接管正常”；音乐反馈：“能听到，播放正常”。
- 用户按慢移、快移、静止约 3 秒、收指后观察约 10 秒进行视觉验收，对局部流动、惯性消散和原画恢复反馈“符合预期”。真实手势山水录像为 30 秒，仅录作品画面；没有使用自动轨迹替代这轮验收。
- 用户补充：摄像头小窗默认打开，手动关闭后才隐藏。已实现主窗口内可关闭的摄像头预览浮层，并实际点击其右上角关闭按钮验证：`Preview=False`、浮层隐藏，摄像头仍为 `ready`，最近识别结果年龄约 21 ms，节点错误为空。详见 [关闭预览验证](validation/preview-close.json)。可用 `Preview` 重新打开，重新启动工程时默认打开。
- 330 秒完整自动轨迹基准平均 58.40 FPS，空闲阶段 51.52 FPS，其余阶段约 59.8–60 FPS，整体 P95 帧间隔 20.41 ms；音乐自然循环一次，静音参数检查通过。此结果未达到全程稳定 60 FPS。
- 缺失资源故障注入验证：启动进入明确错误状态、控制器停止、摄像头停用、速度输入归零；恢复资源定位后重新启动。此测试通过临时替换资源路径实现，没有移动或删除原始素材，记录见 [启动故障验证](validation/missing-resources.json)。
- 新预览浮层版本已重新导出 `.toe`，展开审查确认自动进入 Perform、`Preview` 默认开启、32 位颜色反馈生效，没有开发桥、探针、旧预览系统窗口或存储文件。[交付文件审查](validation/delivery-audit.json) 含工程 SHA-256。用新 TD 进程加载后，摄像头自动进入 `ready`，预览默认显示，短期滚动帧率约 60 FPS；此结果不代替完整五分钟性能验收或断网冷启动。

## 正在验证

- 性能：**尚未达到稳定 60 FPS 的验收结论。** 尝试关闭预览绘制后，300 秒真实控制测量反而下降到 34.59 FPS，已撤回该优化。原生第二窗口开启时约 31 FPS，关闭后同一网络约 60 FPS；调整两窗同步模式仍只有约 32 FPS。改为单窗口浮层后，在长时间运行的开发进程中五分钟平均 37.49 FPS，用户确认一直保持 TD 在前台。新进程复验正在进行，不以短期 60 FPS 或自动轨迹结果代替完整测量。
- 打包：本地 JS、WASM、模型和素材已齐备，并记录 SHA-256。干净 `.toe` 已导出并通过结构审查，新进程正常加载。尚需最新版目录迁移和断网冷启动验证；资源完整性测试不等于离线启动验收。
- 展示：纯净/调试切换、摄像头预览浮层和原生音频节点已实现；音乐实际播放及自然循环已有证据，长时间交互和异常恢复继续验证。
