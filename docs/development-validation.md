## 实现与验证证据

- TD 原生 GPU 节点输出原山水图 1280 × 647；速度平流、旋度、压力投影和图像平流网络无节点错误。速度网格 384 × 194，压力迭代 14 次。
- MediaPipe Tasks Vision 1.0.1 在 TD 内置 Web Render 中使用本地 JS／WASM／模型，识别计算位于独立线程，经 TD Web Server 将最新结果传入控制器。识别目标 20 FPS，渲染独立更新；没有新采样时不重复施力，丢失后安全归零并重建位置基准。
- 16 项 Python 测试与 6 项 Node 测试通过，覆盖有效／无效手势、倾斜、镜像、静止、超时、重复帧、速度限制、单手独占／接管、资源完整性、实体摄像头优先选择、有限重试、识别背压、线程降级及图像释放。
- 原生慢／快轨迹测试发现 16 位图像反馈导致量化残留。改为 32 位图像反馈后，停手 8 秒的相对平均图像差异由约 47%–60% 降至约 2%，所有采样有限。速度场保持 16 位。`Damping=7.67/秒`、`Smoothing=0.035秒`，强度仍为 24。
- 30 秒真实手势录像仅录山水，未录摄像头或关键点；H.264 交付视频完整解码 1801 帧，1280 × 648，作品实际输出仍为 1280 × 647。
- 330 秒混合固定轨迹基准中音乐自然循环一次，静音参数检查通过；TD 与 CEF 聚合私有内存增长约 4.6 MB。
- 缺失资源路径故障注入验证启动进入错误状态、控制器停止、摄像头停用、速度输入归零，恢复路径后正常启动。没有删除或移动原始素材。
- 干净 `.toe` 展开审查确认自动进入 Perform、预览默认开启、32 位图像反馈生效，没有开发桥、探针、旧预览系统窗口或存储文件。SHA-256 见 [交付审查](validation/delivery-audit.json)。

## 性能结果与边界

最终冷启动工程只读观察 300.4 秒，共 298 次每秒采样：滚动 600 帧 FPS 均值 **59.91**，最低 **58.15**；滚动 P95 帧间隔最高 **17.74 ms**。157 次样本检测到手，124 次有激活输入，摄像头始终 `ready`，没有节点错误或状态读取失败。用户确认无明显卡顿。[完整数据](validation/cold-start-performance.json)

这些是相互重叠的滚动窗口统计，采样均值不等于独立逐帧计数的全程平均值；未进行光学端到端延迟测量。五分钟内偶有短时帧率波动，不宣称每一帧严格恒定 60 FPS。

保留失败和对照结果：第二原生预览窗口开启时约 31 FPS，关闭后同一网络约 60 FPS，调整两窗同步仍约 32 FPS，因此交付改为单窗口浮层。关闭预览绘制的尝试曾降至 34.59 FPS，已撤回。反复重载调试后的旧开发进程五分钟为 37.49 FPS，用户确认当时保持 TD 前台；新进程复验数据单独记录，未用短时峰值覆盖旧结果。

当前结论限定在上述本机、最终工程冷启动和实测时长内。小时级连续运行、其他摄像头／显卡和其他 TD 版本尚未验证。视觉结论来自用户直接验收，未声称录制了 Processing 与 TD 的并排对照。
