# PRD：TouchDesigner 摄像头手势交互水墨山水

日期：2026-10-21（北京时间）

状态：需求、模块划分、测试范围及开发任务已由用户确认，作为首版开发依据。

GitHub 父议题：[#1](https://github.com/clouder118/Art-Of-Ink_TD/issues/1)。

任务跟踪目标：[clouder118/Art-Of-Ink_TD](https://github.com/clouder118/Art-Of-Ink_TD/issues)。

仓库边界：用户已指定新建独立的 Art-Of-Ink_TD 仓库。本 TD 版本的文档、任务、工程和后续开发均归入新仓库；Art-Of-Ink 只保留为 Processing 原作基线，不承载 TD 开发提交或任务。

## 问题陈述（Problem Statement）

现有 Art of Ink 是基于 Processing 3.5.4、PixelFlow 和 Minim 的交互式水墨山水作品。观众通过按住鼠标左键并移动，向流体速度场施力，使已有山水图像产生局部流动；程序持续补入原图，维持山水形态。当前作品依赖鼠标和旧版 Processing，尚不能在 TouchDesigner 中通过笔记本摄像头进行自然手势交互。

用户希望在 TouchDesigner 中尽量复现原作的视觉体验，将输入简化为单一食指移动，并保留纯净的山水展示。桌面的 Liquid 工程只作为参考，不构成实现方式或节点结构的约束；验收关注最终呈现效果、跟手程度和运行便利性。

## 解决方案（Solution）

交付可直接在本机 TouchDesigner 中打开的工程。笔记本内置摄像头识别观众的手部，当食指伸直、中指／无名指／小指收拢时，以指尖移动推动原山水图像中的局部墨色。拇指可自然放松，手指允许适度倾斜，不要求严格竖直。

交互采用镜像坐标，左右手均可，但每次只允许一只手控制。手势停止或手离开镜头后停止新增推动，已有流动自然消散，并逐步恢复原图。山水画面不叠加骨架或指尖标记；右上角摄像头预览浮层默认打开，手动关闭后进入纯净山水展示且识别继续。调试模式提供识别状态和性能信息。音乐启动后循环播放，可静音。

首次配置可联网，此后应支持离线启动。用户无需单独安装或手动启动外部 Python 程序。允许使用第三方组件和开源资料，但需验证兼容性、离线资源完整性和本机性能。

## 用户故事（User Stories）

1. 作为体验者，我希望看到与 Processing 原作相近的山水构图和墨色，以便保留作品原有意境。
2. 作为体验者，我希望只用笔记本内置摄像头交互，以便不依赖鼠标或专用传感器。
3. 作为体验者，我希望自然伸出食指即可激活交互，以便无需学习复杂手势。
4. 作为体验者，我希望拇指可自然放松、食指可适度倾斜，以便舒适地操作。
5. 作为体验者，我希望其他手势不会持续扰动画面，以便控制清晰可预期。
6. 作为体验者，我希望指尖位置决定画面中的扰动位置，以便准确推动局部墨色。
7. 作为体验者，我希望手移动越快、方向变化越明显时，流动有相应变化，以便获得接近原作的反馈。
8. 作为体验者，我希望保持手指静止时不会持续增加推动力，以便能够停住动作观察画面。
9. 作为体验者，我希望向右、向上移动时，画面中的控制位置也相应移动，以便操作符合镜像直觉。
10. 作为体验者，我希望使用左手或右手都能交互，以便不受惯用手限制。
11. 作为体验者，我希望另一只手进入镜头时不会抢走控制权，以便画面不突然跳动。
12. 作为体验者，我希望当前控制手退出后，另一只有效手可以接管，以便自然更换操作手。
13. 作为体验者，我希望手势失效或手离开镜头时停止施力，以便作品不会自行持续受到输入。
14. 作为体验者，我希望重新进入镜头或切换手后不会产生跨屏冲击，以便交互连续可信。
15. 作为体验者，我希望停止动作后水墨继续自然流动并逐步恢复山水，以便画面保留呼吸感和可辨识的构图。
16. 作为体验者，我希望正常手部微抖不会变成明显画面抖动，以便获得稳定体验。
17. 作为体验者，我希望流畅度优先，并以稳定 60 FPS 为优化目标，以便动作反馈跟手。
18. 作为观众，我希望默认显示右上角摄像头预览小窗；手动关闭后获得纯净山水展示且仍可继续交互，并能通过维护参数重新显示。
19. 作为展示者，我希望画面以 1280 × 647 渲染，并等比适配全屏，以便兼容现有环境且不拉伸山水。
20. 作为展示者，我希望《山居吟》在作品启动后循环播放，以便持续展示时音乐不会结束。
21. 作为展示者，我希望能够静音，以便适应现场环境。
22. 作为展示者，我希望直接打开 TD 工程即可开始使用，以便不需要手动启动另一个识别程序。
23. 作为展示者，我希望首次配置完成后断网也能重新打开工程并识别手势，以便展示不依赖现场网络。
24. 作为维护者，我希望在调试模式中查看摄像头、手势有效性、控制手、交互位置和帧率，以便定位识别与渲染问题。
25. 作为维护者，我希望摄像头不可用或识别数据过期时画面停止接受推动，并能看到明确状态，以便避免失控或难以排查的停滞。
26. 作为维护者，我希望识别与渲染可以使用不同更新频率，以便识别开销不会拖住画面。
27. 作为维护者，我希望从工程目录读取模型、组件和素材，以便项目不依赖开发者桌面上的绝对路径。
28. 作为项目所有者，我希望新工程保留原始 Processing 和 Liquid 参考项目，以便可以随时回看原作。
29. 作为项目所有者，我希望使用开源参考时保留来源、版本与许可证说明，以便后续维护和交付可追溯。
30. 作为项目所有者，我希望获得启动、离线配置、调试及验收说明，以便自己维护和展示作品。

## 实施决策（Implementation Decisions）

### 已确认的产品边界

- 以原山水图和原作左键拖动效果为基准；接受不同流体实现的细节差异，不要求像素级一致。
- Liquid 仅供参考，允许重建流体核心或采用其他方案。不能为了复用节点牺牲最终效果。
- 保留速度扰动交互，不提供右键温度交互或其他面向观众的新增手势。
- 输入采用摄像头单食指手势；静止时不持续施力，移动速度决定推动强度。
- 左右手通用、单手独占。当前手保持控制权；有效退出后才允许另一只手接管。
- 手势失效、跟踪丢失或输入过期时停止新增施力；流体仍继续演化。重新激活时重新建立位置基准，不能使用丢失前的位置计算大幅位移。
- 山水本身隐藏所有识别叠加层。摄像头预览以主窗口内的可关闭浮层默认打开，关闭只隐藏预览，不关闭识别；重新打开工程恢复默认打开。完整识别与性能状态在调试模式显示。
- 输出为 1280 × 647，等比适配显示区域，必要时留边。
- 音乐自动循环，提供静音；维护控件不作为新增观众交互。
- 以稳定 60 FPS 为首要性能目标，必要时降低模拟网格分辨率或计算次数。用户已将此前“最低 30 FPS 可接受”的建议改为“优先保证流畅度”，因此不能用 30 FPS 宣告性能达标。
- 首版验收环境为本机 Windows、TouchDesigner 2025.32820、RTX 4060 Laptop GPU、笔记本内置摄像头；单人、正常室内光线、手部完整可见。
- 工程及配套资源在仓库的独立 TD 交付区域组织；保留原作和参考工程。具体目录安排记录在交付任务中，不作为运行接口。

### 已确认的模块边界

| 模块 | 简单外部接口与职责 | 封装的复杂性 |
| --- | --- | --- |
| 摄像头与手部识别适配器 | 输入摄像头配置；输出带采集／结果时间信息、有效性、手部关键点和可用身份信息的识别帧 | 设备选择、组件接入、模型加载、数据格式与更新频率 |
| 手势交互核心 | 输入识别帧和时间；输出激活状态、归一化位置、速度及控制手状态 | 手势判定、防抖、单手控制权、镜像映射、平滑、超时与重新激活 |
| 山水流体核心 | 输入原图与交互采样；输出山水流体画面 | 速度施力、图像输运、消散、原图持续补入、数值稳定与精度参数 |
| 展示与声音 | 输入画面、状态和维护设置；输出纯净展示与循环音频 | 等比显示、调试开关、静音及参数可见性 |
| 启动与资源管理 | 输入工程位置和设置；完成本地资源定位并输出启动状态 | 离线资源、相对路径、第三方组件版本、缺失资源诊断 |

模块不等于任务拆分。每个开发任务应跨越所需模块，交付一条能实际演示的完整使用路径。

### 技术方向与尚未验证的假设

- 优先评估 TD 内集成的手部识别组件；内部允许本地 Web 渲染与模型推理，但不能要求用户另开浏览器或手动启动外部服务。
- 流体可使用 GLSL／GPU 网格求解，参考速度与颜色场输运方案；具体实现由效果、性能和兼容性验证决定，尚未锁定第三方流体组件。
- 渲染更新与识别结果更新解耦。渲染可使用最近有效结果，但必须检查新鲜度，不能把同一结果重复视作新的手指位移。
- 识别帧率、手势阈值、平滑程度、控制区域、速度增益、恢复时间等属于可调实现参数，不新增用户手势。
- 识别超时和失效确认应在响应速度与防抖之间折中；具体阈值通过实测确定，不在无数据时承诺固定值。
- 手指移动到图像边缘时应有明确的坐标边界处理，留边不计入山水交互区域。
- 首次配置后离线运行和 60 FPS 均是交付目标，目前未验证，不能视作已有能力。若候选组件不能达到要求，应替换或适配方案；无法满足时明确记录问题，不能静默改为依赖在线资源或外部 Python。
- 冷启动后默认山水展示及摄像头预览小窗，摄像头初始化期间不向画面发送无效施力。

## 测试决策（Testing Decisions）

以下测试范围已随方案确认，作为开发约定。仓库目前没有测试框架或可复用的测试先例。

### 自动化与可重放验证

1. **手势交互核心为重点**：以录制或合成的关键点序列验证自然食指、错误手势、左右手、独占控制、跟踪丢失、输入超时、重新激活和切换手。只断言输出行为，不依赖节点名或内部实现。
2. **坐标与速度**：验证镜像方向、上下方向、边界、静止零推动、不同采样间隔下速度合理、同一识别结果不被重复积分，以及恢复跟踪时不出现跨屏速度尖峰。
3. **流体核心**：用固定交互轨迹验证局部推动、快慢变化、停止后的消散与原图回归。检查画面尺寸、空输入稳定性和输出无异常值；视觉判断使用同条件录像，避免脆弱的逐像素相等测试。
4. **启动与资源**：验证工程移至新目录仍能找到资源，缺失模型／组件时提供明确诊断；首次配置后断网冷启动，不能只验证已缓存会话。
5. **展示与音频**：做工程级冒烟验证，检查纯净展示、等比缩放、调试切换、音乐循环和静音，不为静态布局编写镜像实现的单元测试。

### 本机集成与人工验收

- 用真实内置摄像头演示两种惯用手、自然食指、失效手势、退出与重新进入、另一只手进入及控制权交接。
- 在相同山水图和近似操作轨迹下对照 Processing 原作录像，人工判断局部流动、推动感、消散和恢复是否接近目标；截图或自动化测试不能替代视觉验收。
- 正式展示模式和识别同时启用，在本机记录帧率、帧耗时、跟踪更新率及可测的响应延迟；说明测量方法和条件。建议覆盖空闲、慢速／快速移动、丢失与接管，以及持续运行。
- 性能首要目标为稳定 60 FPS。建议记录持续 5 分钟的平均帧率、帧耗时 P95 与明显卡顿次数，用于调参比较；该测量窗口是建议验证方法，不是已由用户确认的数值门槛。
- 响应延迟需要报告实测结果；之前提出的约 200 毫秒仅作为参考目标，不把缺少测量的主观“跟手”替代数据。
- 在正式构建上进行断网、关闭并重新打开工程的测试，验证无额外程序启动步骤，识别、画面和音频均工作。

## 范围外（Out of Scope）

- 双手同时施力、多点交互及多人展览中的操作者选择。
- 复杂光照、严重遮挡、极端手部姿态等环境下的鲁棒性保证。
- 鼠标作为正式交互入口、右键温度交互、原版键盘操作的逐项复刻或新增手势。
- 像素级复刻 PixelFlow、严格复用 Liquid 节点、将 Processing 代码直接逐行翻译。
- 高于已确认输出规格的高清／多屏／投影适配。
- 音乐驱动画面、换曲系统、作品编辑器、录像导出或独立可执行程序打包。
- 跨操作系统、其他 TD 版本或其他硬件的兼容性保证。
- 修改原 Processing 程序、原始 Liquid 工程，或在本轮直接开始功能开发。

## 补充说明（Further Notes）

### 当前事实与基线

- Processing 主程序使用 1583 × 800 视口；左键移动按位移注入速度，作用半径为 25，速度系数为 15。
- 原图第一步完全注入，之后按每步 0.009 混合补入；这些数值只作视觉基线，不要求不同时间步与分辨率的 TD 实现机械照抄。
- 原作密度／速度／温度保留系数为 0.99／0.88／0.70，涡度为 0.50。TD 首版不需要暴露温度交互。
- 原音乐为单次播放；新作循环播放是已确认的变化。
- 原 Processing 作品仍需使用 3.5.4；其最新版显示兼容性提醒继续保留，与 TD 运行要求分别说明。
- 已在临时目录中展开并读取 Liquid 工程；主要由噪声、反馈与图像位移组成，其保存版本与本机 TD 2025.32820 一致。它没有被修改，也没有被认定为最终流体方案。

### 可参考的开源资料

- [touchFluid](https://github.com/kamindustries/touchFluid)：TD / GLSL 二维流体求解器，含速度及颜色场输运，可作实现与接口参考，尚未在本机验证。
- [MediaPipe TouchDesigner](https://github.com/torinmb/mediapipe-touchdesigner)：TD 内集成手部识别的候选组件，需验证指定 TD 版本和本地资源运行。
- [WebGL Fluid Simulation](https://github.com/PavelDoGreat/WebGL-Fluid-Simulation)：流体运动、GPU 实现与交互反馈参考，不意味着改为交付网页。
- [MediaPipe 手部关键点文档](https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker/python)：关键点与识别能力参考，不意味着必须使用 Python 运行路线。
